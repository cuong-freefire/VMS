## Step 2: Backend Implementation (4-6 hours)

### 2.1 Implement EventService.deleteEvent()

**File**: `backend/src/services/event.service.js`

**Key implementation points** (see `data-model.md` for full code):

1. Wrap in Prisma transaction for ACID guarantee
2. Fetch event and verify not already deleted
3. Ownership validation (organization_id match)
4. Status validation (DRAFT/PUBLISHED/CANCELLED only)
5. Application count check (must be 0)
6. Set `deleted_at` timestamp
7. Create audit log entry

**Estimated Lines**: ~120 lines

**Helper Functions**:

```javascript
// Add to event.service.js

/**
 * Validate event status allows deletion
 */
function validateDeletableStatus(event) {
  const NON_DELETABLE_STATUSES = ['IN_PROGRESS', 'COMPLETED'];
  
  if (NON_DELETABLE_STATUSES.includes(event.status)) {
    throw new ConflictError(
      `Cannot delete events with status: ${event.status}. ` +
      `Only DRAFT, PUBLISHED, and CANCELLED events can be deleted.`,
      {
        eventId: event.id,
        currentStatus: event.status,
        deletableStatuses: ['DRAFT', 'PUBLISHED', 'CANCELLED']
      }
    );
  }
}

/**
 * Validate no applications exist
 */
function validateNoApplications(eventId, appCount) {
  if (appCount > 0) {
    throw new ConflictError(
      `Cannot delete event with existing applications. ` +
      `Found ${appCount} application(s). Please cancel the event instead.`,
      {
        eventId,
        applicationCount: appCount,
        suggestion: 'Use "Cancel Event" feature to handle events with applications'
      }
    );
  }
}
```

### 2.2 Implement EventController.deleteEvent()

**File**: `backend/src/controllers/event.controller.js`

```javascript
/**
 * @swagger
 * /api/v1/events/{id}:
 *   delete:
 *     summary: Delete event (soft delete)
 *     tags: [Events]
 *     security:
 *       - cookieAuth: []
 *     parameters:
 *       - in: path
 *         name: id
 *         required: true
 *         schema:
 *           type: integer
 *     responses:
 *       200:
 *         description: Event deleted successfully
 *       401:
 *         description: Unauthorized
 *       403:
 *         description: Forbidden
 *       404:
 *         description: Event not found
 *       409:
 *         description: Business rule violation
 */
export const deleteEvent = async (req, res, next) => {
  try {
    const eventId = parseInt(req.params.id);
    
    // Validate event ID
    if (isNaN(eventId)) {
      throw new ValidationError('Event ID must be a valid integer');
    }
    
    const staffId = req.user.user_id;
    const organizationId = req.user.organization_id;
    
    // Call service
    const result = await EventService.deleteEvent(
      eventId,
      staffId,
      organizationId
    );
    
    return res.json({
      success: true,
      message: 'Event deleted successfully',
      data: {
        id: result.event.id,
        title: result.event.title,
        status: result.event.status,
        deleted_at: result.event.deleted_at
      }
    });
  } catch (error) {
    next(error);
  }
};
```

## Troubleshooting

### Issue 1: Migration Fails

**Symptom**: `prisma migrate dev` fails with foreign key error

**Solution**:

```bash
# Check if event_audit_log table exists (from UC16)
mysql -u root -p vms_db -e "SHOW TABLES LIKE 'event_audit_log';"

# If not, run UC16 migrations first
cd backend
npx prisma migrate deploy
```

### Issue 2: Existing Queries Broken

**Symptom**: 404 errors for existing events after UC17 deployment

**Solution**:

```bash
# Find queries missing deleted_at filter
cd backend
grep -r "prisma.events.find" src/ | grep -v "deleted_at"

# Update each file to add deleted_at: null filter
```

### Issue 3: Audit Log Not Created

**Symptom**: Event deleted but no audit log entry

**Solution**:

```bash
# Check if event_audit_log table exists
mysql -u root -p vms_db -e "SHOW TABLES LIKE 'event_audit_log';"

# Check service layer transaction logic
grep -A 30 "event_audit_log.create" backend/src/services/event.service.js
```

### Issue 4: Transaction Deadlock

**Symptom**: 500 error with "Deadlock detected" message

**Solution**:

```bash
# Check MySQL isolation level
mysql -u root -p vms_db -e "SELECT @@transaction_isolation;"

# Expected: READ-COMMITTED or REPEATABLE-READ

# If deadlocks persist, add retry logic:
const MAX_RETRIES = 3;
for (let i = 0; i < MAX_RETRIES; i++) {
  try {
    return await prisma.$transaction(async (tx) => {
      // ... delete logic
    });
  } catch (error) {
    if (error.code === 'P2034' && i < MAX_RETRIES - 1) {
      continue; // Retry on deadlock
    }
    throw error;
  }
}
```

### Issue 5: Cannot Delete PUBLISHED Event

**Symptom**: 409 error when trying to delete PUBLISHED event with no applications

**Solution**:

```bash
# Verify application count
mysql -u root -p vms_db -e "SELECT COUNT(*) FROM volunteer_applications WHERE event_id = 123;"

# Expected: 0

# If count > 0, check application statuses
mysql -u root -p vms_db -e "SELECT status, COUNT(*) FROM volunteer_applications WHERE event_id = 123 GROUP BY status;"

# Even REJECTED applications block deletion (by design)
```
