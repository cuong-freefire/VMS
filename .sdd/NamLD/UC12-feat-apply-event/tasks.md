# Tasks: UC12 - Apply Event

## Task Summary

UC12 implements the authenticated Volunteer Apply Event flow from the public Event Detail page `/events/:id`. UC12 is the first NamLD use case that must persist real application data in MySQL through Prisma.

This task file only describes implementation tasks. It does not generate code, install packages, create Prisma schema, create or run migrations, modify `.env`, or change source files by itself.

## Dependencies

- UC12 context, spec, and plan are the primary source for this task breakdown.
- UC09 Event Detail page is the frontend entry point: `/events/:id`.
- UC09 Event Detail remains public for Guest and authenticated users.
- UC12 Apply API is protected and requires authenticated role `VOLUNTEER`.
- Canonical backend path relative to `/api/v1` is:

```http
POST /events/:eventId/applications
```

- Runtime endpoint is:

```http
POST /api/v1/events/:eventId/applications
```

- Frontend API client path should be:

```txt
/events/${eventId}/applications
```

- Do not use deprecated alias `POST /events/:id/apply`.
- Do not use nested response wrapper `data.application` unless `API_CONTRACTS.md` is updated later.
- Success response follows `API_CONTRACTS.md` direct `data` shape with `applicationId`, `event`, `volunteerId`, `status`, `message`, and `createdAt`.
- New application status is `PENDING`.
- `approvedParticipants` must not increase when Volunteer applies; it increases only when Staff approves in a later UC.
- UC12 does not implement UC13 View Applied Events, UC14 Cancel Application, UC48 Feedback, or UC51/UC52 Certificate.
- Real MySQL credentials must not be written in docs/tasks/source.
- `.env` must not be committed.
